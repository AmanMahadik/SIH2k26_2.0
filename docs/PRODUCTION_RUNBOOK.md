## 1. Cloud Architecture & Provisioned Resources

### 1.1 Azure Database for PostgreSQL (Flexible Server)
- **Host:** `aicte-nirikshai-db.postgres.database.azure.com`
- **Port:** `5432`
- **Database:** `nirikshai`
- **Region:** Central India (Pune)
- **SKU:** Standard D2ds_v5 (2 vCores, 8 GiB RAM)
- **Security:** TLS 1.3 enforced, SSL mode `require`, Azure private endpoints enabled.
- **Tables:** `inspections`, `inspection_media`, `labs`, `officers`, `audit_log`, `institutions`, `applications`.

### 1.2 Azure Blob Storage (Evidence Media)
- **Account:** `nirikshaistorage`
- **Container:** `inspection-evidence`
- **Access Model:** No public container access. Writes require short-lived SAS tokens generated by `/api/inspections/sas` (TTL: 15 minutes, write-only permission).

## 3. Database Migration & Schema Maintenance

All migrations reside in `db/migrations/` and must be executed in order:
1. `001_initial_schema.sql`: Core master institutions, applications, OCR fields.
2. `002_evc_inspections.sql`: EVC field inspections, statutory labs, geodetic compound indexes, append-only cryptographic audit logs.

### Running Migrations:
```bash
node scratch/run-migration.mjs
```

## 4. Cryptographic Non-Repudiation (Section 65B Compliance)

Every field inspection submitted from the mobile app passes through SHA-256 block hash chaining:
$$\text{blockHash}_i = \text{SHA256}(\text{blockHash}_{i-1} \parallel \text{canonicalEvent}_i)$$

- Genesis block: 64 zero characters `0000...0000`.
- Verify audit chain integrity anytime via:
```bash
GET /api/audit/verify
```
If any database row is tampered with, the endpoint flags the exact block index and reports verification failure.

## 5. Security & Network Hardening

1. **Helmet-Style Headers:** Enforced via `next.config.mjs` (CSP, Strict-Transport-Security, X-Frame-Options SAMEORIGIN, X-Content-Type-Options nosniff).
2. **Server-Side Verification:** Client coordinate claims are never trusted alone. The server re-computes the Haversine distance against the stored lab centroid and flags discrepancies.
3. **Mock Location Detection:** Android `location.mocked` is checked at kernel level; mock fixes are rejected and logged to the audit ledger.
